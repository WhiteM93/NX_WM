# NX_WM

Мои постпроцессоры для Siemens NX2506 и события (UDE) для щупа. Станок - Fanuc 0i-MF Plus, щуп Hexagon. Привязка и измерения идут через макросы O9101, O9102, O9103 (вызов `G65 P9101` / `P9102` / `P9103`).

Репозиторий: https://github.com/WhiteM93/NX_WM

## Что тут лежит

Папки постов не переименовывайте, на эти пути завязаны установщик и `template_post.dat`.

- `1.ai_3ax` - 3 оси, Fanuc, плюс щуп (On Machine Probing и мои события привязки). Основной пост, в списке NX называется так же.
- `1.ai_4ax` - 4 оси с осью A. Установщик папку копирует, но в список постов NX не добавляет, это надо руками.
- `2.Cutter CH` - 3 оси, в NX виден как `2.Cutter_CH`.
- `3.Sicono` - 3 оси, в NX `3.Sicono_cnc`.

Раньше были ещё `1.ai_3ax_omp` и `1.ai_3ax_probe`, 3 ноября 2026 я их слил в `1.ai_3ax`. Если в старых операциях стоит один из них, переключите на `1.ai_3ax`. Установщик старые папки сохраняет в бэкап и потом удаляет из NX (спросит перед этим).

Если операция начинается без смены инструмента, `1.ai_3ax` после ускоренного по XY выводит `G43 Z.. H..` и `M08` (если СОЖ не выключена). В операциях щупа этого кадра нет, там щуп сам подходит и даёт свой G43.

Общий список событий - `ude_wm.cdl`, он подключает `probe_omp.cdl`, `probe_wall_check.cdl`, `probe_set.cdl` и стандартный `ude.cdl`. Сами CDL и tcl щупа лежат в `1.ai_3ax`. В `configuration/cam_general.dat` поменяна одна строка `USER_DEFINED_EVENTS`, она указывает на `${UGII_CAM_POST_DIR}ude_wm.cdl`. Оригинал от Siemens лежит рядом, `cam_general.dat.siemens_original`, на случай отката. `ugpost_base.tcl` и `ugpost_base_math.tcl` - базовые файлы Siemens, их установщик трогает только с ключом `-IncludeBase`.

CDL сохранять только в Windows-1251 и с CRLF, иначе NX2506 их читает криво. Обработчики `MOM_*` грузятся из папки поста, а если не нашлись - из `$env(UGII_CAM_POST_DIR)/1.ai_3ax/`.

## Установка

Клонируем репозиторий (или `git pull`, если уже есть), закрываем NX. Если ugraf.exe висит в процессах, установщик дальше не пойдёт.

```bat
git clone https://github.com/WhiteM93/NX_WM.git
install.bat -DryRun
install.bat
```

`-DryRun` ничего не пишет, просто показывает, что поменяется. Потом обычный запуск, он попросит админа (UAC) и окно в конце не закроет, можно спокойно почитать что он сделал.

NX2506 ищется сам: сначала по `UGII_BASE_DIR`, потом в `C:`, `D:`, `E:\Program Files\Siemens\NX2506`. Не нашёл - укажите вручную:

```bat
install.bat -NxDir "D:\Program Files\Siemens\NX2506"
```

Посты и `ude_wm.cdl` копируются в `<NX>\MACH\resource\postprocessor\`. Перед правкой `template_post.dat` и `cam_general.dat` он спрашивает, надо ввести `д`. В список постов добавляются только строки из репозитория, в `cam_general.dat` меняется только `USER_DEFINED_EVENTS`. Бэкап и лог пишутся в `E:\NX_Tools\Backup\nx_install_<время>\`, если диска E: нет - спросит куда.

Ключи (работают и с `install.bat`, и с `install.ps1`):

```
-DryRun              только показать изменения
-Uninstall           откатить последнюю установку
-BackupDir <папка>   откат из конкретного бэкапа
-NxDir <путь>        папка NX, если сам не нашёл
-Yes                 не спрашивать про template_post.dat и cam_general.dat
-IncludeBase         ещё предложить заменить ugpost_base*.tcl
-BackupRoot <папка>  куда класть бэкапы
```

При откате старые файлы возвращаются, а те что установщик добавил новыми - удаляются.

После установки перезапускаем NX и смотрим список UDE. Там должны быть «Привязка центра по 2 точкам», «Привязка Z», Probe set Z top / boss / hole и Probe wall check.

Если NX стоит в Program Files, может вылезти «Отказано в доступе» (`UnauthorizedAccessException`) на `cam_general.dat`. У меня так было. Лечится так: закрыть NX, открыть PowerShell от администратора (Win+X, «Терминал (администратор)») и выполнить

```powershell
attrib -r "C:\Program Files\Siemens\NX2506\MACH\resource\configuration\cam_general.dat"
icacls "C:\Program Files\Siemens\NX2506\MACH\resource" /grant "${env:USERNAME}:(OI)(CI)M" /T
```

Права выдаются один раз, потом установщик идёт и без админа. В PowerShell пишите именно `${env:USERNAME}`, `%USERNAME%` понимает только cmd. Дальше снова `install.bat` и `д`.

Можно и без установщика: скопировать посты и `ude_wm.cdl` в `<NX>\MACH\resource\postprocessor\`, перенести строки из `template_post.dat` в такой же файл NX и заменить строку `USER_DEFINED_EVENTS` в `<NX>\MACH\resource\configuration\cam_general.dat`. Кодировку CDL при этом не трогать.

Обновление:

```bat
git pull
install.bat
```

Если репозиторий склонирован прямо в папку postprocessor (как у меня на работе), хватает `git pull`. `install.bat` нужен, когда менялись `template_post.dat` или `cam_general.dat`, или ставите в другой NX. После правок событий щупа NX обязательно перезапустить, иначе новых полей не увидите.

## События щупа

Все события подключаются через `ude_wm.cdl` и через `INCLUDE` в `1.ai_3ax/ai_3ax.def`. Добавляются в операцию как обычные UDE. В одну операцию можно накидать несколько, M60/M61 всё равно будет одна пара на всю операцию.

`G65 P9101 A1.` / `A0.` включает и выключает щуп, `P9102` - защищённое перемещение, `P9103` - касание. Результат касания: X в `#101`, Y в `#102`, Z в `#103`, диаметр в `#100`.

Про M60/M61. Внутри O9101 щуп включается рабочим ходом `G43 H.. Z.. F..`, а шпиндель стоит, и стойка даёт тревогу 2301. На нашем станке M60 разрешает G01 без шпинделя, M61 возвращает обратно. Поэтому в событиях есть поле «M60/M61 (без шпинделя)», по умолчанию «Да»: M60 перед `G65 P9101 A1.`, M61 после `A0.`. В старых сохранённых событиях поля нет, но M60/M61 там тоже выводятся.

### Привязка центра по 2 точкам (prb_center_axis)

Касаемся в двух точках (направление задают векторы), считается середина, сдвиг пишется в СК через `G91 G10` и сразу `G90`. Подачи: `#170` касание, `#172` перемещение.

| Поле | По умолчанию | Что это |
|------|--------------|---------|
| Точка 1 / 2, Вектор 1 / 2 | - | где и в какую сторону касаться |
| Расстояние подвода | 5.0 | отход от точки до касания |
| Безопасная Z | 50.0 | высота переездов |
| Подача измерения / перемещения | 1000 / 3000 | `#170` и `#172`, выводятся всегда |
| Включать щуп | По станку | Да / Нет / как в настройке поста |
| M60/M61 (без шпинделя) | Да | см. выше |
| Высота касания | По точкам | или одна общая «Z касания» |
| СК движения щупа | Из операции | G54-G59 или G54.1 (тогда ещё «P для G54.1») |
| Записать привязку в | В СК движения | другая СК или «Не записывать» (только мерить) |
| Контроль размера | Нет | «Номинал (0 = по модели)» и «Допуск +/-» (0.05), вне допуска `#3000` и ноль не пишется |

Вот что выдаёт пост (это по X, по Y точно так же):

```nc
#170=1000. (PODACHA KASANIYA)
#172=3000. (PODACHA PEREMESHCHENIYA)
#171=1. (NOL W)
M60
G65 P9101 A1.
#183=#0
#184=#0
#185=#0
#186=#0
G65 P9102 Z-4.753 F#172
G65 P9103 X-100.
#183=#101
G65 P9102 X-110. F#172
G65 P9102 Z50. F#172
G65 P9102 X110. Y47.327 F#172
G65 P9102 Z-6.057 F#172
G65 P9103 X100.
#184=#101
G65 P9102 X110. F#172
G65 P9102 Z50. F#172
#185=[#183+#184]/2
#186=#185-0.
(CENTR X = #185, SDVIG = #186)
G91 G10 L2 P1 X#186
G90
G65 P9101 A0.
M61
```

С контролем размера перед записью добавляется:

```nc
#188=ABS[#184-#183]
#189=#188-<номинал>
(RAZMER = #188, OTKLONENIE = #189, NOM ... +... -...)
IF[#189GT...]#3000=1(RAZMER BOLSHE DOPUSKA)
IF[#189LT-...]#3000=2(RAZMER MENSHE DOPUSKA)
```

### Привязка Z (prb_z_point)

Одно касание сверху в точке из NX, сдвиг Z через `G91 G10` и `G90`. Сделано так же, как центр по 2 точкам.

| Поле | По умолчанию | Что это |
|------|--------------|---------|
| Точка касания (верх) | - | XY - где касаться, Z - номинал в режиме «По точке» |
| Расстояние подвода / Безопасная Z | 5.0 / 50.0 | |
| Подача измерения / перемещения | 1000 / 3000 | `#170` и `#172` |
| Включать щуп / M60/M61 | По станку / Да | как в центре |
| Номинал Z | По точке | или «Задать» и поле «Z номинал (Задать)» |
| Доп. смещение Z | 0.0 | прибавляется к сдвигу после контроля высоты |
| СК движения / запись | Из операции / В СК движения | G54-G59, G54.1 или «Не записывать» |
| Контроль высоты | Нет | допуск ±0.1, вне допуска `#3000` и ноль не пишется |

Номинал 0, подвод 5, безопасная 50:

```nc
#170=1000. (PODACHA KASANIYA)
#172=3000. (PODACHA PEREMESHCHENIYA)
#171=1. (NOL W)
M60
G65 P9101 A1.
#183=#0
#186=#0
G65 P9102 Z5. F#172
G65 P9103 Z0.
#183=#103
G65 P9102 Z50. F#172
#186=#183-0.
(Z = #183, SDVIG = #186)
G91 G10 L2 P1 Z#186
G90
G65 P9101 A0.
M61
```

Касание идёт ровно до номинала. Если верх детали ниже модели, щуп может не дотянуться и будет «нет касания».

### Probe set Z top / boss center / hole center

Это старые события, ноль пишут сами макросы `P9103`, номер нуля в `#171` (W). Подачи по умолчанию не задаются, макросы берут свою `#111`. Если включить «Feed override», появляется `#170` и `F#170` на подводах. У одиночного касания `P9103 Z..` подачи нет никогда, у бобышки и отверстия (`D`) есть `F#170`, если override включён.

Поля: точка XY (Z точки не используется), Z safe 50, Z approach 10, Feed override, M60/M61, Zero W (1-6 это G54-G59, `-n` это G54.1 Pn), инструмент щупа T/H 20. У бобышки и отверстия ещё Diameter D 50 и Z depth -10, у Z top - Z nominal 0.

Бобышка D50, глубина -10, подвод Z10, W1, T20, override включён:

```nc
#170=1000. (PODACHA PODVODA)
#171=1. (NOL W)
G00 G90 G53 Z0.
T20 M06
G00 G90 G54 X0. Y0.
G43 H20 Z50.
M60
G65 P9101 A1.
G65 P9102 Z10. F#170
G65 P9103 D-50. Z-10. W#171 F#170
G65 P9102 Z50. F#170
G65 P9101 A0.
M61
```

Z top вместо цикла `D` даёт одно касание `G65 P9103 Z<номинал> W#171` без F. Отверстие: сначала опускается `G65 P9102 Z<глубина>`, потом `G65 P9103 D<диаметр> W#171`.

### Probe wall check (probe_wall_check)

Два касания стенки и сравнение. По умолчанию значения в `#190` и `#191`, разница в `#192`. Больше допуска - тревога `#3000`.

Поля: T/H 20, Feed override, M60/M61, рабочая СК (G54-G59 / G54.1 и P), точки 1 и 2, Z touch 15, Z safe 50, расстояние касания 20, направление X+ / X- / Y+ / Y- (по умолчанию Y-), допуск 0.1, номера переменных 152-199 (по умолчанию 190 / 191 / 192).

Пример: Y-, точки (-97, 80) и (97, 80), без override:

```nc
G00 G90 G54 X-97. Y80.
G43 H20 Z50.
M60
G65 P9101 A1.
#190=#0
#191=#0
#192=#0
G65 P9102 Z15.
G65 P9103 A91. Y-20.
#190=#102 (Y1)
G65 P9102 Z50.
G65 P9102 X97. Y80.
G65 P9102 Z15.
G65 P9103 A91. Y-20.
#191=#102 (Y2)
G65 P9102 Z50.
G65 P9101 A0.
M61
#192=ABS[#191-#190]
IF[#192GT0.1]THEN#3000=99(STENKA RAZNICA BOLSHE 0.1)
```

## Правила для макросов

Это то, на чём я уже обжигался, так что лучше соблюдать.

Свои переменные беру только из `#152`-`#199`. `#170` - подача касания (в привязке центра и Z, а в Probe set и wall check только при Feed override). `#171` - номер нуля W, 1-6 это G54-G59, отрицательный - G54.1. `#172` - подача перемещения на `P9102` в привязке центра и Z. `#190`-`#192` заняты под wall check.

GOTO не использую. M60/M61 только вокруг `G65 P9101 A1.` / `A0.`, больше нигде.

XY и Z в одном кадре не ставить никогда. Сначала Z, потом XY, при подъёме наоборот, отдельными `P9102`.

После любого `G91`, в том числе `G91 G10`, сразу `G90`. Смещение пишется `G91 G10 L2 P..` для G54-G59 или `L20` для G54.1.

Одиночное касание `P9103` по X/Y/Z идёт без F. Цикл `P9103 D..` может быть с `F#170`.

Текст в `#3000` и `#3006` не длиннее 26 символов. Комментарии в кадрах щупа только транслитом, без кириллицы.

## Если что-то не работает

Тревога 2301 на `G65 P9101 A1.` - значит нет M60. Проверьте, что в событии «M60/M61 (без шпинделя)» стоит «Да», перезапустите NX и спроцессируйте заново.

«Отказано в доступе» при установке - смотрите выше про Program Files.

NX не стартует с «Fatal initialization error: Terminating due to unable to find valid directory to create syslog file». У меня это было на домашнем компе при запуске из Пуска. Помог ярлык, в котором для процесса заданы `TEMP`, `TMP` и `UGII_TMP_DIR` на короткий путь латиницей, например `E:\NX_Temp2`. Через него запускается нормально.
