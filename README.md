# NX_WM — постпроцессоры Siemens NX CAM

Набор постпроцессоров для **Siemens NX2506** и пользовательских событий (UDE) под стойку **Fanuc 0i-MF Plus** со щупом **Hexagon**. Измерения и привязка идут через макросы `O9101` / `O9102` / `O9103` (`G65 P9101` / `P9102` / `P9103`).

Репозиторий: [github.com/WhiteM93/NX_WM](https://github.com/WhiteM93/NX_WM).

## Посты

Папки постов **не переименовывать**: установщик и `template_post.dat` ссылаются на эти пути. Имя в списке NX может отличаться от имени папки (см. таблицу).

| Папка | Имя в `template_post.dat` | Назначение |
|-------|---------------------------|------------|
| `1.ai_3ax` | `1.ai_3ax` | 3-осевой фрезерный (FANUC) + щуп: On Machine Probing и UDE привязки |
| `1.ai_4ax` | *не добавляется* | 4-осевой фрезерный (ось A). Установщик копирует папку, но строку в список постов NX не вставляет |
| `2.Cutter CH` | `2.Cutter_CH` | 3-осевой фрезерный |
| `3.Sicono` | `3.Sicono_cnc` | 3-осевой фрезерный |

Посты `1.ai_3ax_omp` и `1.ai_3ax_probe` 3 ноября 2026 объединены в `1.ai_3ax`. Если в старых операциях выбран один из них, переключите пост на `1.ai_3ax`. Установщик сохраняет эти папки в резервную копию и удаляет их из NX (после подтверждения).

В `1.ai_3ax` при старте операции без смены инструмента после XY-ускоренного выводится `G43 Z.. H..` и `M08` (если СОЖ не выключена). В операциях щупа этот кадр пропускается: щуп выводит свой подвод и `G43`.

## Структура репозитория

| Путь | Назначение |
|------|------------|
| `1.ai_3ax/` | Пост `ai_3ax.tcl` / `.def` / `.pui` и события щупа (`probe_omp`, `probe_set`, `probe_wall_check`) |
| `1.ai_4ax/`, `2.Cutter CH/`, `3.Sicono/` | Остальные посты (`.tcl`, `.def`, `.pui`) |
| `ude_wm.cdl` | Общий список UDE: подключает `probe_omp.cdl`, `probe_wall_check.cdl`, `probe_set.cdl` и стандартный `ude.cdl` NX |
| `configuration/cam_general.dat` | В репозитории изменена только строка `USER_DEFINED_EVENTS` → `${UGII_CAM_POST_DIR}ude_wm.cdl`. Оригинал Siemens: `cam_general.dat.siemens_original` |
| `template_post.dat` | Строки списка постов, которые установщик добавляет или заменяет в NX |
| `install.bat`, `install.ps1` | Установщик в папку NX |
| `ugpost_base.tcl`, `ugpost_base_math.tcl` | Базовые файлы Siemens; установщик предлагает заменить их только с `-IncludeBase` |

CDL-файлы нужно сохранять в **Windows-1251**, перевод строки **CRLF** (так их читает NX2506). Обработчики `MOM_*` подгружаются из папки поста через `info script`, при неудаче — из `$env(UGII_CAM_POST_DIR)/1.ai_3ax/`.

## Установка

1. Склонируйте репозиторий (`git clone https://github.com/WhiteM93/NX_WM.git`) или сделайте `git pull` в уже существующей папке.
2. **Закройте NX** (`ugraf.exe`). Если он запущен, установщик остановится.
3. Сначала проверка, без записи: `install.bat -DryRun`.
4. Установка: `install.bat`. Скрипт запрашивает права администратора (UAC) и оставляет окно открытым, чтобы можно было прочитать результат.

`install.bat` запускает `install.ps1`. Установщик сам ищет NX2506 (`UGII_BASE_DIR`, затем `C:`, `D:`, `E:\Program Files\Siemens\NX2506`). Если не нашёл — укажите путь: `install.bat -NxDir "D:\Program Files\Siemens\NX2506"`.

Что делает установка:

- копирует папки постов и `ude_wm.cdl` в `<NX>\MACH\resource\postprocessor\`;
- для `template_post.dat` и `cam_general.dat` отдельно спрашивает подтверждение (введите `д`): в список постов вносятся только строки из репозитория, в `cam_general.dat` меняется только `USER_DEFINED_EVENTS`;
- если в NX ещё лежат папки `1.ai_3ax_omp` / `1.ai_3ax_probe`, после подтверждения (`д`) сохраняет их в резервную копию и удаляет;
- резервная копия и лог: `E:\NX_Tools\Backup\nx_install_<время>\` (если диска E: нет, установщик спросит папку).

Полезные параметры (их можно передать и в `install.bat`, и в `install.ps1`):

| Параметр | Назначение |
|----------|------------|
| `-DryRun` | Только показать, что будет изменено |
| `-Uninstall` | Откатить последнюю установку из резервной копии |
| `-BackupDir <папка>` | Откат из указанной резервной копии |
| `-NxDir <путь>` | Папка NX, если она не найдена автоматически |
| `-Yes` | Не спрашивать подтверждение для `template_post.dat` / `cam_general.dat` |
| `-IncludeBase` | Также предложить заменить `ugpost_base*.tcl` |
| `-BackupRoot <папка>` | Куда класть резервные копии |

Откат: `install.bat -Uninstall` (или с `-BackupDir`). Восстанавливаются файлы, которые уже были, и удаляются те, что установщик добавил как новые.

После установки перезапустите NX и проверьте список UDE: должны быть «Привязка центра по 2 точкам», «Привязка Z», Probe set Z top / boss / hole и Probe wall check.

### Если NX стоит в Program Files (ошибка «Отказано в доступе»)

Файлы в `C:\Program Files\...` (или `D:\Program Files\...`) по умолчанию защищены от записи, поэтому `cam_general.dat` может не записаться (`UnauthorizedAccessException`).

1. Закройте NX.
2. Откройте PowerShell **от имени администратора** (Win+X → «Терминал (администратор)»).
3. Снимите «только чтение»:
   ```powershell
   attrib -r "C:\Program Files\Siemens\NX2506\MACH\resource\configuration\cam_general.dat"
   ```
4. Один раз выдайте себе права на папку `resource` (дальше установщик можно запускать без администратора):
   ```powershell
   icacls "C:\Program Files\Siemens\NX2506\MACH\resource" /grant "${env:USERNAME}:(OI)(CI)M" /T
   ```
   В PowerShell пишите именно `${env:USERNAME}`; `%USERNAME%` работает только в cmd.
5. Снова запустите `install.bat` (или `& ".\install.ps1"`) и подтвердите `д`.

### Ручная установка

1. Скопировать папки постов и `ude_wm.cdl` в `<NX>\MACH\resource\postprocessor\`.
2. Добавить или заменить строки из `template_post.dat` репозитория в `template_post.dat` установки NX.
3. В `<NX>\MACH\resource\configuration\cam_general.dat` заменить строку `USER_DEFINED_EVENTS` на строку из репозитория.

Кодировку CDL (Windows-1251, CRLF) не менять.

## Обновление

```bat
git pull
install.bat
```

Если репозиторий уже лежит прямо в папке постпроцессоров NX, для файлов постов и UDE достаточно `git pull`. `install.bat` нужен, когда менялись `template_post.dat` или `cam_general.dat`, либо когда файлы ставятся в другую установку NX.

После правки событий щупа **перезапустите NX**, иначе новое поле в UDE может не появиться.

## События щупа (UDE)

Все события подключаются через `ude_wm.cdl` (строка `USER_DEFINED_EVENTS` в `cam_general.dat`) и через `INCLUDE` в `1.ai_3ax/ai_3ax.def`. Добавляются в операцию щупа так же, как обычные UDE NX. Несколько событий в одной операции допустимы: пара `M60` / `M61` на всю операцию одна.

Макросы: `G65 P9101 A1.` / `A0.` — включить / выключить щуп; `G65 P9102` — защищённый подвод; `G65 P9103` — касание. Результаты: X → `#101`, Y → `#102`, Z → `#103`, диаметр D → `#100`.

Поле **«M60/M61 (без шпинделя)»** по умолчанию «Да»: перед `G65 P9101 A1.` выводится `M60`, после `A0.` — `M61`. Это нужно на данной стойке, чтобы внутри `O9101` разрешить `G01` при остановленном шпинделе (иначе тревога 2301). Если поля ещё нет в старом сохранённом событии, `M60` / `M61` тоже выводятся.

### Привязка центра по 2 точкам (`prb_center_axis`)

Касание двух точек (векторы задают направление), расчёт середины и запись сдвига в СК через `G91 G10` … `G90`. Подачи: `#170` (касание), `#172` (перемещение).

| Поле | По умолчанию | Назначение |
|------|--------------|------------|
| Точка 1 / Точка 2, Вектор 1 / Вектор 2 | — | Места и направления касания (указываются в NX) |
| Расстояние подвода | 5.0 | Отход от точки до касания |
| Безопасная Z | 50.0 | Высота переездов |
| Подача измерения / перемещения | 1000 / 3000 | `#170` и `#172` (всегда выводятся) |
| Включать щуп | По станку | `Да` / `Нет` / как в настройке поста |
| M60/M61 (без шпинделя) | Да | См. выше |
| Высота касания | По точкам | Или одна общая «Z касания» |
| СК движения щупа | Из операции | G54–G59 или G54.1 (тогда ещё «P для G54.1») |
| Записать привязку в | В СК движения | Другая СК, либо «Не записывать» (только измерение) |
| Контроль размера | Нет | Если «Да» — допуск относительно номинала; при выходе за допуск `#3000` и запись нуля не выполняется. «Номинал (0 = по модели)», «Допуск +/−» (по умолчанию 0.05) |

Пример (фрагмент, привязка по X, затем так же по Y):

```nc
#170=1000. (PODACHA KASANIYA)
#172=3000. (PODACHA PEREMESHCHENIYA)
#171=1. (NOL W)
M60
G65 P9101 A1.
#183=#0
#184=#0
#185=#0
#186=#0
G65 P9102 Z-4.753 F#172
G65 P9103 X-100.
#183=#101
G65 P9102 X-110. F#172
G65 P9102 Z50. F#172
G65 P9102 X110. Y47.327 F#172
G65 P9102 Z-6.057 F#172
G65 P9103 X100.
#184=#101
G65 P9102 X110. F#172
G65 P9102 Z50. F#172
#185=[#183+#184]/2
#186=#185-0.
(CENTR X = #185, SDVIG = #186)
G91 G10 L2 P1 X#186
G90
G65 P9101 A0.
M61
```

При включённом контроле размера перед записью нуля добавляется:

```nc
#188=ABS[#184-#183]
#189=#188-<номинал>
(RAZMER = #188, OTKLONENIE = #189, NOM ... +... -...)
IF[#189GT...]#3000=1(RAZMER BOLSHE DOPUSKA)
IF[#189LT-...]#3000=2(RAZMER MENSHE DOPUSKA)
```

### Привязка Z (`prb_z_point`)

Одно касание сверху в точке из NX (или с заданным номиналом Z) и запись сдвига Z через `G91 G10` … `G90`. Стиль тот же, что у центра по 2 точкам.

| Поле | По умолчанию | Назначение |
|------|--------------|------------|
| Точка касания (верх) | — | XY — место касания, Z — номинал при режиме «По точке» |
| Расстояние подвода / Безопасная Z | 5.0 / 50.0 | Подвод сверху и высота переездов |
| Подача измерения / перемещения | 1000 / 3000 | `#170` и `#172` |
| Включать щуп / M60/M61 | По станку / Да | Как в привязке центра |
| Номинал Z | По точке | Либо «Задать» и поле «Z номинал (Задать)» |
| Доп. смещение Z | 0.0 | Прибавляется к сдвигу после контроля высоты |
| СК движения / запись | Из операции / В СК движения | G54–G59, G54.1 или «Не записывать» |
| Контроль высоты | Нет | Допуск ±0.1; при выходе за допуск `#3000` и ноль не записывается |

Пример (номинал Z = 0, подвод 5, безопасная Z = 50):

```nc
#170=1000. (PODACHA KASANIYA)
#172=3000. (PODACHA PEREMESHCHENIYA)
#171=1. (NOL W)
M60
G65 P9101 A1.
#183=#0
#186=#0
G65 P9102 Z5. F#172
G65 P9103 Z0.
#183=#103
G65 P9102 Z50. F#172
#186=#183-0.
(Z = #183, SDVIG = #186)
G91 G10 L2 P1 Z#186
G90
G65 P9101 A0.
M61
```

Цель касания ставится ровно на номинал. Если верх детали ниже модели, щуп может не дотянуться («нет касания»).

### Probe set Z top / boss center / hole center

Старые события записи нуля макросами `P9103` с номером нуля в `#171` (W). Подачи по умолчанию не переопределяются (макросы используют свою `#111`); поле «Feed override» включает `#170` и `F#170` на подводах. У одиночного касания `P9103 Z..` подачи нет; у циклов бобышки/отверстия (`D`) подача `F#170` есть, если override включён.

Общие поля: точка XY (Z точки игнорируется), Z safe (50), Z approach (10), Feed override, M60/M61, Zero W (`1…6` = G54…G59, отрицательное число `−n` = G54.1 Pn), номер инструмента щупа T/H (20). Для бобышки и отверстия дополнительно Diameter D (50) и Z depth (−10). Для Z top — Z nominal (0).

Пример, бобышка (D50, глубина −10, подвод Z10, W1, T20, override включён):

```nc
#170=1000. (PODACHA PODVODA)
#171=1. (NOL W)
G00 G90 G53 Z0.
T20 M06
G00 G90 G54 X0. Y0.
G43 H20 Z50.
M60
G65 P9101 A1.
G65 P9102 Z10. F#170
G65 P9103 D-50. Z-10. W#171 F#170
G65 P9102 Z50. F#170
G65 P9101 A0.
M61
```

Z top вместо цикла `D` делает одно касание: `G65 P9103 Z<номинал> W#171` (без F). Отверстие: подвод на глубину `G65 P9102 Z<глубина>`, затем `G65 P9103 D<диаметр> W#171`.

### Probe wall check (`probe_wall_check`)

Проверка разницы двух касаний стенки (по умолчанию в переменных `#190`, `#191`, разница `#192`). Если разница больше допуска — тревога `#3000`.

Поля: номер инструмента T/H (20), Feed override, M60/M61, рабочая СК (G54…G59 / G54.1 и P), точка 1 и 2, Z touch (15), Z safe (50), расстояние касания (20), направление `X+` / `X−` / `Y+` / `Y−` (по умолчанию `Y−`), допуск (0.1), номера переменных (152–199, по умолчанию 190 / 191 / 192).

Пример (Y−, точки (−97, 80) и (97, 80), без override подачи):

```nc
G00 G90 G54 X-97. Y80.
G43 H20 Z50.
M60
G65 P9101 A1.
#190=#0
#191=#0
#192=#0
G65 P9102 Z15.
G65 P9103 A91. Y-20.
#190=#102 (Y1)
G65 P9102 Z50.
G65 P9102 X97. Y80.
G65 P9102 Z15.
G65 P9103 A91. Y-20.
#191=#102 (Y2)
G65 P9102 Z50.
G65 P9101 A0.
M61
#192=ABS[#191-#190]
IF[#192GT0.1]THEN#3000=99(STENKA RAZNICA BOLSHE 0.1)
```

## Правила макропеременных и кадров

- Свои переменные — только `#152`–`#199`.
- `#170` — подача касания (в событиях привязки центра и Z; в Probe set / wall check — только если включён Feed override).
- `#171` — номер нуля W (1…6 = G54…G59; отрицательное — G54.1).
- `#172` — подача перемещения в UDE «Привязка центра по 2 точкам» и «Привязка Z» (`F#172` на `P9102`).
- `#190`–`#192` зарезервированы под Probe wall check (так заданы значения по умолчанию).
- `GOTO` не использовать.
- `M60` / `M61` — только вокруг `G65 P9101 A1.` / `A0.`.
- Никогда не ставить XY и Z в одном кадре. Подвод: сначала Z, потом XY (или наоборот при подъёме), отдельными `P9102`.
- После кадра `G91` (в том числе `G91 G10 …`) всегда возвращать `G90`.
- Одиночное касание `P9103` (ось X/Y/Z) — **без F**. Цикл `P9103 D…` (бобышка / отверстие) может иметь `F#170`.
- Текст тревоги `#3000` / сообщения `#3006` — не длиннее 26 символов.
- Запись смещения: `G91 G10 L2` (G54–G59) или `L20` (G54.1) `P…` и сразу `G90`.

Комментарии в кадрах щупа — латиницей (транслит), без кириллицы.

## Устранение неполадок

**Тревога 2301 (G01 при остановленном шпинделе).** Внутри `O9101` щуп включается рабочим перемещением `G43 H… Z… F…`. На этой стойке перед `G65 P9101 A1.` нужен `M60`, после `A0.` — `M61`. В событиях щупа оставьте «M60/M61 (без шпинделя)» = «Да», перезапустите NX и спроцессируйте заново.

**«Отказано в доступе» / `UnauthorizedAccessException` при установке.** См. [права на Program Files](#если-nx-стоит-в-program-files-ошибка-отказано-в-доступе).

**NX не стартует: «Fatal initialization error: Terminating due to unable to find valid directory to create syslog file».** Запуск из меню Пуск может падать, если рабочий каталог или `TEMP`/`TMP` неудобны для syslog. Запускайте NX ярлыком, у которого в переменных процесса заданы `TEMP`, `TMP` и `UGII_TMP_DIR` на короткий путь из латинских символов (например `E:\NX_Temp2`).
